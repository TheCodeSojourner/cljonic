Human direction 2026-11-06: retain cljonic's idiomatic conversion preflight plus direct destination-value return, rather than checked-result wrappers. Every implementation must provide a selectable diagnostic mode; applications may instead choose normal mode. On runtime conversion failure, diagnostic mode records a static diagnostic and stops execution without returning a value; normal mode returns a documented fallback. Operations are non-throwing, non-allocating, and avoid invalid underlying C++ conversions.

Diagnostic state follows REQ-PLAT-012/013's single-threaded/caller-confinement model; no extra synchronization is required. Human approval: normal-mode failure returns the maximum integer value, largest finite floating value, all-bits-set byte, or NUL for `char` (not a valid cljonic String character). Other fallbacks can equal a successful result; callers who need certainty use preflight. Human approval: a normal-mode fallback passed downstream is an ordinary value; the receiving API applies its own checks and does not infer prior failure. No hidden failure flag exists. Diagnostic mode stores a compact error code in a static variable, then calls an application-provided non-returning handler which may inspect it and must not throw, allocate, or deallocate. Human approval: handler compliance is the application's responsibility, verified by review and target-specific tests; cljonic does not claim to detect returning or allocating. Returning from the [[noreturn]] handler is not recoverable conversion failure. Runtime message construction is not required. Mode is compile-time configured: default 0 normal, 1 diagnostic, reject other values; select before including cljonic and keep consistent across translation units. Diagnostic builds provide a function matching a prescribed declaration; no library default or runtime registration. Normal mode needs no definition, while a reachable diagnostic failure path without one fails to link. Each `to_*` has a `can_to_*` preflight and `to<T>` has `can_to<T>`. Preflight accepts the same sources and policies, returns true exactly when conversion succeeds for the same value/policy, and never records a diagnostic or calls the handler. Human approval: false preflight followed by the same conversion triggers configured failure; diagnostic classification uses the same failed conditions and precedence across all conversion domains, without requiring caching. Unsupported source types are compile-time rejections. Approved diagnostic categories: out of range, precision loss, non-finite input, nonzero underflow to zero, invalid character, and unsupported signed zero. Failed preflights do not change diagnostic state; unsupported type/policy combinations are compile-time rejections. If failures overlap, select the first applicable category: non-finite input, invalid character, unsupported signed zero, out of range, underflow to zero, precision loss. Classify under the selected policy; precedence affects the diagnostic only. Human approval: a scoped `ConversionError` enum contains `none`, `non_finite_input`, `invalid_character`, `unsupported_signed_zero`, `out_of_range`, `underflow_to_zero`, and `precision_loss`; static state starts at `none` and is set before calling the handler. Human approval: enum is `cljonic::core::ConversionError`; non-throwing, non-allocating read-only `cljonic::core::conversion_error()` returns the library-managed code. Normal mode has no diagnostic-state storage, handler reference, registration, or initialization, and the accessor returns `none`; this does not imply zero conversion-checking or executable-code overhead. Human approval: diagnostic mode has one library-managed static error code shared across the application's translation units; successful conversions and all preflights leave it unchanged. The handler can read a failure from any translation unit. Visibility depends on target/build; reset persistence is not guaranteed. No reset API is required. Human approved the compile-time mode macro `CLJONIC_CONVERSION_DIAGNOSTICS` and handler declaration `[[noreturn]] void cljonic::core::conversion_failure_handler() noexcept`. Conversion outcome is classified default-returning in normal mode with a documented non-returning diagnostic exception; constant-evaluation failure is separate and preflights are Boolean predicates (REQ-ERR-009). REQ-ERR-007 has a narrow exception for the approved conversion diagnostic mode's static error state and non-returning handler; no other safety protections are relaxed. Constant-evaluation rejection stays as previously specified. REQ-NUM-010 and architecture record the decisions.
