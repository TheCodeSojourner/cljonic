template<typename Predicate, typename Source>
using cljonic::DropWhile = concepts_detail::PredicateProducer<Predicate, Source, true>

drop_while(predicate, source) returns a producer that skips values from the start of source while predicate returns true. It keeps the first value for which the predicate returns false and every value after it, without calling the predicate again. An empty source or a predicate that returns true for every inspected value gives an empty result.

Pass any cljonic collection or producer as the source. The predicate must return bool, accept a const source element without throwing, and must not allocate. Declare lambdas noexcept and avoid side effects, as with filter. Source and predicate must be copyable without throwing; captured lambdas are supported.

The result keeps its own copies of the inputs and leaves them unchanged. Creating it does not evaluate values; accessing its first value may scan all initial values for which the predicate returns true. Each traversal starts again, so count followed by consumption can run callbacks twice. If a source callback depends on changing external data, the two traversals may give different results.

Even an unbounded source is inspected only up to the configured collection maximum. Skipped values count toward that limit: with a limit of 100 and three skipped values, at most 97 values remain. Map and Set have no guaranteed traversal order, so use an ordered source when a particular suffix matters. External C++ ranges and individual MapEntry values are not accepted as sources.

next and rest preserve the producer type and defer omitting one output element, without evaluating callbacks at tail creation. Observation replays the original prefix removal, then skips output; it never reapplies prefix removal to the retained suffix. A Cycle over this producer also supports tails, determining its bounded source length eagerly.

The equal free function compares one or more values for equality.

Equal compares values by their contents:

  • Calling equal with one value always returns true.

  • Two ordinary values compare equal when they are the same type, or types that convert safely to one another, and compare equal with == (e.g., int, a scoped enum, or a user-defined class with an explicit or defaulted operator==). int and long compare equal when they hold the same number, because a safe conversion never changes a value; comparing a signed value against an unsigned one, or a character against a number, is not supported. The comparison must not throw, so a type whose == can throw is not supported; pointers and unscoped enums are not supported either.

    A user-defined class states its own equality contract, and the library never inspects its members: whether it is a plain aggregate struct or a class with its own constructors, it is supported when == cannot throw. The library makes no claim about whether that == is correct, including for floating-point members. A non-aggregate class is supported on the same terms that admit it as a map key or a set element.

  • Sets compare equal when they hold the same elements, regardless of insertion order.
  • Strings compare equal when they hold the same characters.

Collections are never compared to ordinary values. Values that cannot be compared stably, such as floating-point numbers, are not supported.

Iterate and Repeatedly values cannot be compared stably because their step is a callable, so they are not supported as map keys, set elements, or nested components. Standard-library range and container types are not supported at any depth.

Nested collections and composite values compare by the same rules; a nested producer that admits stable equality is compared by its stored parameters.

The into free function inserts values from a cljonic collection or producer into a copy of a Vector, Set, Map, Queue, or String.

Returns the destination's type, leaving both destination and source unchanged. Vector and Queue append at the end or rear. Set ignores duplicate values. Map accepts MapEntry values of its declared entry type and replaces matching keys; the last processed entry for a key wins. String appends characters in traversal order. Invalid characters fail constant evaluation; at runtime they are replaced with '.' and traversal continues.

Values are processed in source traversal order. When full, a Set accepts an existing value as a no-op and a Map accepts a MapEntry with an existing key as a value replacement. Vector and Queue cannot accept more values when full. String also stops at capacity, independently of character validity. Processing stops before the first value that needs unavailable capacity, without skipping it to process later values. An unbounded source remains limited to its configured observable traversal cap, even if Set or Map insertion does not increase the result count for duplicates or matching keys. Use fits_into beforehand when complete materialization matters.

Source values must follow the destination's safe implicit conversion rules. External C++ range or view sources are not supported.

#include "cljonic.hpp"
using namespace cljonic;
int main() {

constexpr auto destination = vector<int, 8>(100, 200);
constexpr auto source = Range{0, 5};

The map free function applies its transforming function to corresponding elements of one or more cljonic sources. The function is the first argument, followed by one or more sources: a Vector, Map, Set, Queue, or String collection, or a Range, Repeat, Cycle, Iterate, or Repeatedly producer. A unary function is applied over one source, a binary function over two sources, and so on; traversal terminates when the first source is exhausted. Map and Set traversal order is not semantically significant, so the mapped result order carries no semantic significance for those sources.

The result is a bounded owning Vector of the function results. Its capacity is the compile-time minimum of the sources' observable-count bounds: a collection contributes its declared capacity and any producer contributes the configured observable traversal cap, every contribution saturated at CLJONIC_COLLECTION_MAXIMUM_ELEMENT_COUNT_VALUE. The runtime number of mapped elements is the minimum of the sources' effective counts: a collection contributes its element count, a finite producer its count, and an unbounded producer its configured observable traversal cap. Every source value is preserved.

The transforming function must be copy-constructible, invoked without throwing with one argument per source, and return a storable element result. Each parameter must accept the corresponding source element through a safe implicit conversion: an identical type, or a value-preserving arithmetic conversion such as int to long. A narrowing conversion such as long to int, and any conversion that crosses the Boolean, character, enumeration, pointer, or user-defined domains, is rejected at compile time. A callback whose parameter types are not statically inspectable – a generic lambda, or a class with a templated operator() – is admitted on nothrow invocation alone. Standard-library ranges and containers, functions that can throw, and results that cannot be stored are rejected at compile time.

template<concepts_detail::NextSequenceableCollection C>
auto cljonic::next ( const C & collection) -> concepts_detail::NextResult< C >::type
nodiscardconstexprnoexcept

The next free function returns the logical tail of a Vector, Map, Set, Queue, or String as a value of the same collection kind, or of a supported producer as an owning value of the same producer kind. The input remains unchanged.

The result has a static capacity of one less than the source (zero when the source capacity is zero) and contains every logical element after the first in the source's traversal order. An empty or singleton input returns an empty value of the result type.

A map's elements remain value-semantic map_entry values. Map and Set traversal order is not semantically significant, while Queue retains FIFO order.

For a finite counted Repeat, the result is finite with the same repeated value and one fewer count, saturating at zero. For an unbounded Repeat, the result remains unbounded with its observation policy unchanged.

For a Range, the result preserves its endpoint and step. A zero-step Range remains unbounded, an empty finite Range is unchanged, and a singleton finite Range becomes empty at its endpoint without adding the step. Otherwise, the start advances by one step.

For a Cycle, the result starts at the next value and keeps cycling through the whole source. For example, cycling 1, 2, 3 becomes 2, 3, 1, 2, 3, ..., not 2, 3, 2, 3, .... An empty source stays empty. A Cycle over an unbounded producer continues from that producer's next value. Each traversal of the resulting Cycle can still yield up to CLJONIC_COLLECTION_MAXIMUM_ELEMENT_COUNT_VALUE values; calling next does not reduce that limit. When cycling a TakeWhile or DropWhile result, calling next first counts that result within its bounded window, so source and predicate callbacks may run during the call.

For TakeWhile and DropWhile, next returns the same producer type with its first output value removed. For example, if take_while yields 1, 2, its tail yields 2; if drop_while yields 4, 1, its tail yields 1, without testing that retained value against the predicate again. Calling next itself does not run callbacks; they run when you observe the result. Skipping values does not extend the original source window or cross a TakeWhile stopping point. Repeated calls eventually give an empty result, which stays empty. These rules also apply to nested producers.

For an Iterate, next invokes the step once and uses its result as the returned producer's initial value while preserving the observation cap. A zero observation cap does not invoke the step.

For a Repeatedly, next invokes a copy of the step once, discards that produced value, and stores the advanced step copy in the tail. A finite Repeatedly tail has one fewer element; an unbounded Repeatedly keeps its observation cap. An empty Repeatedly does not invoke its step. Value-held mutable state advances in the returned Repeatedly only, while effects through referenced or static state occur when next is called and remain shared.

For all callback-backed producers, observing the same producer again may rerun callbacks rather than reuse earlier results. This includes Iterate and Repeatedly, as well as TakeWhile, DropWhile, and Cycles over them. Callbacks should idiomatically be pure; Repeatedly is an explicitly permitted exception that may use stateful callbacks or side effects. Each Iterate traversal starts from its stored initial value. Each Repeatedly traversal starts with a fresh copy of its stored callback, so mutable state held by value restarts, while referenced or static state remains shared. Where external side effects are permitted, they may repeat; changing external state can change later observations, including which values a Cycle repeats.

Calling next does not materialize the remaining producer sequence into a collection.

The reduce free function folds a cljonic source into a single value. Two forms are available: reduce(f, source) starts from the source's first element, and reduce(f, initial, source) starts from an initial value. The source is a Vector, Map, Set, Queue, or String collection, or a Range, Repeat, Cycle, Iterate, or Repeatedly producer.

The reducing function is called as f(accumulator, element) from left to right and must return the accumulator type. Its result type is therefore always the same as its first parameter type. The accumulator must be a storable element type, and the function must be copyable and non-throwing.

The accumulator type is the function's first parameter type when its parameters can be inspected. Because the first form has no initial value to supply that type, its function must be inspectable: a generic callable whose parameter types cannot be inspected must use the form with an explicit initial value, where the initial value's type becomes the accumulator type.

reduce visits count(source) elements, capped at CLJONIC_COLLECTION_MAXIMUM_ELEMENT_COUNT_VALUE, so an unbounded producer is folded over its observable traversal cap and every call terminates. It never stops early. Over an empty source, the form without an initial value returns the accumulator's default value; the form with an initial value returns that initial value. Map and Set traversal order is not semantically significant, so a fold over those sources depends on the function's own commutativity. Every source value is preserved.

Without an initial value, the first source element must convert safely to the accumulator type. In either form, each callback parameter must safely accept its corresponding argument; when an initial value is supplied, it must also convert safely to the accumulator type. Safe conversion means an identical type or a value-preserving conversion such as int to long. A narrowing conversion such as long to int, and any conversion that crosses the Boolean, character, enumeration, pointer, or user-defined domains, is rejected at compile time. ◆ rest() [1/2]

template<concepts_detail::NextSequenceable C>
auto cljonic::rest ( const C & value) -> decltype(next(value))
nodiscardconstexprnoexcept

The rest free function is an alias for next over the same supported input domain. It returns exactly the result of next(value), preserving its result type, logical tail, input, producer observation policy, and callback timing and effects.

For collections, the result has the same collection kind with one less capacity (zero stays zero), and contains every logical element after the first. Map elements remain value-semantic map_entry values. Map and Set traversal order is not semantically significant, while Queue retains FIFO order. Unlike pop, rest follows logical traversal order rather than the collection-specific removal end.

For producers, rest preserves all of next's producer-specific tail behavior, including the eager callback timing of Iterate and Repeatedly, deferred callback-free TakeWhile and DropWhile tail creation, and eager bounded length determination for finite adapter-source Cycles.

int main() {

constexpr auto remainder = rest(values);

static_assert(remainder(0) == 20 && remainder(1) == 30);

constexpr auto queue_remainder = rest(queue_values);
static_assert(first(queue_remainder) == 5 &&
first(rest(queue_remainder)) == 6);
static_assert(count(rest(vector<int, 0>())) == 0);

template<typename Count, typename Source>

auto cljonic::take ( Count count,

nodiscardconstexprnoexcept

The take free function returns the first requested elements of one cljonic source as a bounded owning Vector. Use take(count, source) with a Vector, Map, Set, Queue, or String collection, or a Range, Repeat, Cycle, Iterate, or Repeatedly producer.

Counts follow the safe count conversion rules: signed or unsigned integers whose nonnegative ranges fit std::size_t, excluding Boolean and character types. Zero or negative counts return an empty vector. A request larger than the source's observable count returns all observable elements. The result has the source element type and its declared collection capacity, or the configured observation cap for a producer, saturated at CLJONIC_COLLECTION_MAXIMUM_ELEMENT_COUNT_VALUE. Capacity does not depend on the runtime count.

The result follows source traversal order; Map and Set order is not semantically significant. Queue traversal is FIFO, String yields characters, and Map yields MapEntry values. Empty requests do not start traversal, and no producer is advanced past the last returned element. The source value is preserved. Repeatedly callback state held by value is preserved; referenced or static state remains shared. MapEntry inputs and external C++ ranges are not supported. The operation is constexpr, non-throwing, and non-allocating.

#include "cljonic.hpp"
using namespace cljonic;
int main() {

static_assert(equal(take(10, values), values));

const auto source = queue(10, 20, 30, 40);
const auto runtime_prefix = take(requested, source);
const auto generated =
take(requested, iterate([](int value) noexcept { return value + 1; }, 5));
return equal(runtime_prefix, vector(10, 20, 30)) &&
